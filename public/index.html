Encryption Flow
HOW YOUR DATA STAYS PRIVATE
01
Server Generates Salt
When a room is created, the server generates a cryptographically random 32-byte salt unique to that room. This salt is sent to all clients joining the room.
salt = crypto.randomBytes(32).toString('base64')
02
Client Derives Keys Locally
Your browser uses PBKDF2 with 200,000 iterations to derive two 256-bit keys from the room code + salt. An encryption key (AES-256-GCM) and a signing key (HMAC-SHA256). Keys never leave your device.
PBKDF2(roomCode + salt, 200000 iter) → [encKey | hmacKey]
03
Encrypt Before Sending
Each message is encrypted with AES-256-GCM using a freshly generated 96-bit random IV. The ciphertext is then signed with HMAC-SHA256 to create an integrity proof.
ct = AES-GCM(encKey, randomIV, plaintext) → sign(hmacKey, iv+ct)
04
Server Relays Ciphertext
The server stores and relays only the encrypted payload — ciphertext, IV, and HMAC signature. It has no ability to decrypt messages because it never possesses the room code.
server.store({ ciphertext, iv, sig }) // opaque to server
05
Verify Then Decrypt
Recipients first verify the HMAC signature. If valid, AES-GCM decryption proceeds. A failed signature shows a red "TAMPERED" warning — the message was modified in transit.
if HMAC.verify(sig) → AES-GCM.decrypt(ct) else → WARN: TAMPERED
